# Native bridge contract — integration pending

Initial transport, credential attachment, activation/dialogue gates and server checks are compiled as a disabled-by-default candidate. This contract still defines the incomplete full integration boundary; see NATIVE_STAGE_STATUS.md.

1. **Identity and reconnect.** Native client persists character UUID in supported per-save co-save data. Server maps the authenticated transport session to a campaign/player credential after checking build, plugin/runtime fingerprints, character lineage and current campaign revision. Do not derive ownership from names, IPs, transient actor IDs or party leadership. Keep automatic party join and normal mutation disabled until reconciliation passes. Starting/reconnecting is not proof that old local inventory is current.
2. **Threading.** Worker/engine hooks must not perform blocking HTTP. Server uses a bounded asynchronous queue to the host's loopback service; client-to-server requests use the existing encrypted game transport. Publish only validated immutable permission snapshots to the client. If permission has not arrived, prevent the local action and retry through the main-thread runner after a grant. The game host must forward only authenticated actor identities and must not trust user-supplied campaign IDs.
3. **Followers.** Observe actual supported-framework recruitment/dismissal, preserve plugin-qualified reference identity and use compare-and-set records. SFF aliases and SKSE helpers need adapters; custom followers require individual state mappings. Unsupported generated FF references are held pending until their UUID mapping is proved. Only the recruiter controls talk, commands, dismissal, trade, pickpocket and hotkey paths. Other clients replay visuals/voice and combat. AI simulation ownership stays separate from persistent follower ownership. An offline record marked parked requires a verified game-side parking procedure; do not delete or clone the actor as a substitute. Quest-required followers and scenes need explicit compatible exceptions.
4. **Dialogue.** Client prechecks NPC activation and menu-choice execution before fragments run. Server classifies known quest/service interactions and issues an expiring actor-specific grant. Cache token+generation; renew while the valid interaction continues, release on close/unload/death/disconnect. Server validates all related activation/inventory/quest requests. Preserve forcegreets, scripted scenes, ambient speech and player services through tested adapters. Blocking sound or denying a packet after a fragment executes is insufficient. A lease's grant alone does not establish that an engine menu is open.
5. **Items.** The curated artifact catalog identifies logical uniqueness; each object/stack also needs a permanent instance UUID. Transfer follows reserve -> source removal receipt -> destination addition receipt -> ledger commit. Actual engine operations need their own durable idempotency marker: database replay suppression alone cannot prevent a second native credit. The native bridge must recover a lost response by checking its receipt/instance marker, never by blindly executing the operation again. Keep unresolved items unavailable and block checkpointing while any transfer is pending. Observe player/follower/storage/vendor/world/corpse/display paths and supported consumption/crafting/disenchant. Complete metadata reconstruction and unsupported-mod handling are required before importing items.
6. **Checkpoints.** Native safe-point acknowledgements must precede save capture. File stability/header/hash checks alone cannot certify a Papyrus VM or world checkpoint. All players' saves, necessary co-saves, relevant per-mod external state, compatibility fingerprints and matching campaign revision must commit together. The current exporter deliberately labels current-database vs historical model state; no restore-to-game API exists. Future rollback must restore a coherent supported world and ledger with a new campaign epoch rather than reusing stale network leases/operation receipts.
7. **Solo progress.** No offline quest/world merger is implemented or advertised. A supported import must name a common checkpoint and a new branch identity, track exact supported deltas and consume its import ID once. Unknown quests/scripts, conflicting artifacts, NPC death or changed mod fingerprints stop the import and preserve both source saves. Character-XP, skill points and perks need Experience/Static Skill Leveling adapters; do not sum snapshots or invoke level rewards twice.

Build/live deployment remain separate. The host PC is connected and native builds plus isolated transport/API tests pass. Terra is offline; no two-player gameplay validation has run. Existing source-only exception permits experimental development but does not certify guessed engine behavior.
